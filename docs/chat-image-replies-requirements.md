# 聊天图片回复需求与计划

## 目标

让桌宠在对话中展示 AI 接口返回的图片，保留文字、Emoji、动作旁白和已有聊天记录。此功能接收服务返回的图片，不额外调用独立绘图接口，不保证文字模型具备生图能力。

## 实现范围

1. 解析 Markdown 图片及 OpenAI 兼容 content 图片块、message.images、Gemini 图片 parts；接受 HTTPS 图片和有限大小的 PNG/JPEG/WebP/GIF Base64 图片。
2. 图片作为独立消息片段显示，不进入旁白解析或逐字动画；支持点击展开、加载失败与重试。
3. 图片内容随本机聊天历史保存；后续模型上下文仅保留图片标记，不重复发送图片数据。限制单条图片消息大小，防止历史无限增长。
4. 默认主题与 animal-island 主题均具备图片、按钮和错误状态样式。远程图片使用无 Referer 的请求，不附带 AI 密钥。
5. 不修改用户真实 AI 配置，不将密钥、服务地址或用户图片写入仓库。
6. 发图及出图失败时继续沿用当前伴侣的人设、称呼、关系阶段和上下文，以简短自然的聊天话语承接；避免任务报告、客服套话和无关的 AI 身份声明。保持真实能力说明，不虚构成功结果。普通回复、DeepSeek JSON 和降级回复使用同一要求。
7. 虚拟伴侣聊天中的自拍、生活照请求沿用聊天配文，不主动改写为“角色图”“自拍风”“不是真实自拍”等制作说明。用户明确询问真伪、来源、拍摄事实时再如实解释；不编造现实拍照经历，不从旧消息模仿多余免责声明。

## 验收

- [x] 普通文字、混合图文、纯图片、多个图片回复正确显示。
- [x] 非法地址和不支持的数据格式不执行；图片失败可以重试。
- [x] 图片消息重新打开后保留；上下文去除图片数据。
- [x] 两套主题组件回归通过，类型检查、Rust 相关测试及完整 Tauri 构建通过。
- [x] 发图和失败回复共用伴侣聊天风格规则；普通、JSON 与降级路径已静态核对，相关聊天测试 30 项通过。实际模型对语气规则的遵循效果仍须实聊确认。
- [ ] 实际服务返回图片的联调结果单独记录，不以模拟测试代替。

## 使用方式与边界

1. 在现有 AI 接口设置中选择支持图片输出的服务和模型，保存后正常聊天。
2. 模型可以在文字中使用 Markdown 图片语法，也可以通过受支持的结构化图片块返回图片。桌宠会自动显示，无须增加图片开关。
3. 图片可点击展开、收起，失败时可重试。不执行返回的 HTML，不读取 file/asset 本地路径，不为远程图片附加 API 密钥。
4. 每条消息最多显示 8 张图片，单个图片源最多 4 MiB，完整返回消息最多 8 MiB；超限提示或拒绝，避免保存半段图片数据。
5. 内嵌图片随消息保存在本机数据库；远程图片保存的是原链接，链接失效后不能保证重新显示，不属于永久离线缓存。
6. 本次未增加独立绘图接口、图片上传、模型自动切换或图片保存按钮。只支持文字的模型不会因为界面支持图片就获得生图能力。
7. 发图配文承接当前话题，保留角色的称呼和关系分寸；失败时自然、简短说明，不虚构出图成功。用户主动问能力或故障原因时仍诚实回答。语气通过模型提示约束实现，不靠硬替换返回文本或添加固定台词。
8. 自拍场景补充：不主动使用“自拍风角色图”“不是真实自拍”等制作说明，图片替代文本遵循同样规则；明确询问真伪时如实回答，不编造现实拍照经历。已完成提示规则修改与 30 项聊天逻辑回归；模型实际是否减少这些措辞待实聊确认，不能用逻辑测试代替语气验收。
