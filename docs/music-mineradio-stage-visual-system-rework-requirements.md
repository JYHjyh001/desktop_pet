# Mineradio 式沉浸舞台视觉系统重做需求计划

本文档记录对沉浸音乐模式视觉控制和 WebGL 舞台的二次重做。本次目标是参考 `XxHuberrr/Mineradio` 的舞台化视觉控制方式，把当前按“频谱、线条、波纹”拆分的样式开关，改成面向播放场景的整体舞台预设。本次只调整前端运行态视觉、WebGL 粒子参数和本机枚举偏好，不保存用户歌曲路径、播放 URL、歌词文本、平台 Cookie、token、音频数据或本机运行历史。

## 背景

- 用户反馈当前沉浸视觉仍像频谱插件叠加，不像 Mineradio 的整体播放舞台。
- Mineradio 的产品方向强调歌词舞台、粒子舞台、节奏镜头、视觉预设和性能策略协同，不是把视觉拆成频谱、线条、波纹三个独立按钮。
- 当前项目已有 WebGL 粒子层、自由镜头和歌词居中能力，适合在现有基础上改成舞台预设驱动。

## 目标

1. 沉浸韵律面板改为舞台预设选择：
   - 不再展示“频谱、线条、波纹”三组样式按钮。
   - 使用整体舞台预设卡片表达默认播放态、星河漫游、电影脉冲、长播 DJ、纯歌词等视觉意图。
   - 每个预设同时决定粒子结构、节奏响应、镜头感和 Canvas 回退样式。
2. WebGL 主视觉改成舞台预设驱动：
   - 粒子类型从频谱/线条/波纹语义改为星尘、星云、舞台光带、节拍爆点和轨迹粒子。
   - 增加 GPU 点精灵数量和层次，但继续使用少量 `THREE.Points` draw call，避免 DOM/Canvas 单粒子循环。
   - 不同预设在 shader 中表现不同镜头、光带、爆点和漂浮节奏。
3. 保持旧设置兼容：
   - 旧的 `visualSpectrumStyle`、`visualLineStyle`、`visualRippleStyle` 本机字段继续能读取。
   - 新增 `visualStagePreset` 字段后，界面以舞台预设为准；旧字段只作为 Canvas/WebGL 不可用时的回退映射。
4. 默认主题和 `animal-island` 主题都必须检查：
   - 预设卡、当前状态、强度、歌词偏移、降低动态、提示和错误样式都要可读。
   - 不引入矩形歌词光效，不降低歌词边缘清晰度。

## 非目标

- 不复制 Mineradio 的源码、shader、素材、Logo、命名或 GPL 实现。
- 不接入外部音频识别、音频上传或指纹服务。
- 不修改网易云、酷狗、本地音乐播放链路。
- 不提交 `.env`、真实密钥、用户本机路径、音乐库数据或打包产物。

## 实施步骤

1. 阅读隐私清单、当前沉浸模式、WebGL 组件和 Mineradio 公开说明。
2. 新增 `MusicVisualStagePreset` 类型和预设配置。
3. 调整 `MusicWindow.vue`：
   - 新增 `visualStagePreset` 状态和本机设置读写。
   - 删除沉浸面板中频谱/线条/波纹三组按钮展示。
   - 新增舞台预设卡片，并把预设映射到内部视觉模式和 Canvas 回退样式。
   - 状态文案改成舞台预设文案。
4. 调整 `MusicWebglStarfield.vue`：
   - 接收 `stagePreset`。
   - 粒子几何改成星尘、星云、舞台光带、节拍爆点、轨迹粒子。
   - shader 用 `uStagePreset` 生成不同舞台运动和光效。
5. 调整 `src/styles.css`：
   - 新增舞台预设卡片样式。
   - 移除面板内频谱/线条/波纹按钮样式依赖。
   - 补齐默认主题和 `animal-island` 主题覆盖。
6. 执行 `npm run build`，并用临时页面检查默认主题与 `animal-island`。
7. 通过隐私清单检查后，将本条从未完成功能移动到完成功能。
