# 沉浸歌词音乐融合响应需求计划

状态：已完成。

## 背景

- 当前沉浸歌词已经会跟随 `beat`、`bass`、`mid`、`treble` 和 `volume` 做位移、发光和投影变化。
- 现有响应直接使用当前帧能量，强节拍时变化容易显得突然，歌词和音乐之间更像被参数硬拽动，而不是舞台灯光和歌词对象自然配合。
- 本次只调整前端运行态视觉响应，不保存歌词文本、歌曲路径、播放 URL、平台 Cookie、token、音频数据或本机运行历史。

## 目标

1. 设计并实现一套“歌词音乐融合响应”：
   - 持续音乐能量负责环境呼吸和光晕。
   - 鼓点负责短促但有衰减的轻推。
   - 换句和唱词进度负责歌词入场、进度线亮度和主歌词前移。
2. 减少突兀跳动：
   - 对音频响应使用 attack/release 平滑。
   - 对主歌词位移、Z 轴、光晕和投影做更克制的分层控制。
3. 保留已有用户设置：
   - 不新增面板开关。
   - 保留倾角、溢光、字号、位置、远近、弱化和鼓点溢光。
4. 默认主题和 `animal-island` 主题下均保持歌词清晰可读。

## 非目标

- 不改歌词解析、在线歌词、本机歌词读取和逐字进度算法。
- 不把歌词文字渲染进 WebGL，不做 WebGL 深度遮挡。
- 不新增音频上传、音频指纹识别或外部识别服务。
- 不保存用户歌曲路径、播放 URL、Cookie、token、歌词文本或音频数据。

## 设计

- 新增运行态歌词包络 `lyricMusicEnvelope`：
  - `pulse`：由鼓点和低频驱动，attack 快、release 慢。
  - `breath`：由音量和中频驱动，负责持续环境呼吸。
  - `phrase`：由当前歌词行进度驱动，换句时轻柔入场，中段保持稳定。
  - `air`：由中高频驱动，负责空气感和扫描光。
- CSS 新增变量：
  - `--lyric-music-pulse`
  - `--lyric-music-breath`
  - `--lyric-music-phrase`
  - `--lyric-music-drift`
  - `--lyric-music-focus`
- 原歌词舞台响应改为读取包络变量，减少直接使用瞬时音频值。

## 验收

- [x] 播放时歌词光晕、投影、进度线和主歌词前后位移通过包络响应音乐，视觉变化比直接跳动更柔。
- [x] 换句时有轻柔入场和聚焦，不出现大幅突兀跳变。
- [x] 降低动态开启时禁用明显音乐运动，只保留静态层次。
- [x] 地面 DJ 和星河漫游都使用同一套歌词音乐包络，但保持各自空间位置。
- [x] 默认主题和 `animal-island` 主题下歌词可读。
- [x] `npm run build` 通过。
- [x] `npm run tauri:build` 通过并启动 release 版。
