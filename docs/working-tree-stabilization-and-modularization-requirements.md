# 工作区整理、依赖审计与音乐窗口渐进拆分计划

## 背景

当前 `main` 工作区包含多个阶段积累的安全、音乐、翻译、桌宠窗口、测试和发布工程改动。为了降低误覆盖、回滚困难和发布遗漏风险，本轮先把现有改动按主题保存，再修复生产依赖审计，最后以不改变现有行为为前提开始拆分音乐窗口并补宠物生命周期测试。

本文档只记录通用工程边界，不记录用户本机路径、AI API Key、音乐路径、平台 Cookie、token、播放 URL、聊天内容或运行历史。

## 目标

1. 对当前工作区执行隐私扫描、空白检查和质量验证，并按实际功能主题形成多个可独立回滚的 Git 提交。
2. 修复 `npm audit --omit=dev` 的生产依赖告警。
3. 让本地 `npm run check:ci` 与 GitHub Quality 工作流使用同一条生产依赖审计规则。
4. 从 `MusicWindow.vue` 中拆出一块高内聚、可独立测试的逻辑，保持现有界面和播放行为不变。
5. 为宠物窗口的显示、隐藏、气泡和生命周期清理补充自动化回归测试。
6. 前端改动同时验证默认主题和 `animal-island` 主题。

## 非目标

1. 本轮不新增音乐平台、播放器模式或 AI 功能。
2. 不重写整个音乐窗口，不一次性迁移全部状态。
3. 不修改用户本机配置、音乐库、平台凭据或导入资源。
4. 不推送 GitHub、不发布 Release。

## 实施阶段

### 阶段一：保存现有工作区

- 读取并执行发布隐私检查清单。
- 检查 `.gitignore`、`git status --short`、疑似密钥关键词和 `git diff --check`。
- 按“发布安全与工程基线”“桌宠/AI/翻译基础”“音乐与沉浸体验”等主题分批提交。
- 每个提交使用中文提交信息，并以实际暂存内容生成摘要。

### 阶段二：依赖审计一致性

- 更新锁文件中的安全修复版本，不使用破坏现有 Vue/Tauri 行为的强制大版本升级。
- 将生产依赖审计封装为 npm script。
- 本地 `check:ci` 和 GitHub CI 都调用同一个 script，避免两套规则漂移。
- 验证生产审计、完整依赖审计、前端构建和现有测试。

### 阶段三：音乐窗口渐进拆分

- 优先选择纯计算或状态转换逻辑，而不是直接搬动大型模板。
- 新模块应有清晰输入输出，不直接持有窗口级隐式状态。
- 原窗口通过导入调用新模块，保持现有 DOM、主题类名和用户交互不变。
- 为新模块增加单元测试。

### 阶段四：宠物窗口生命周期测试

- 覆盖挂载后的事件注册与卸载清理。
- 覆盖窗口隐藏后气泡不会再次出现的前端/IPC 行为。
- 覆盖默认主题和 `animal-island` 主题的基础渲染入口。
- 如真实 Tauri Webview 行为无法直接在 jsdom 中模拟，将关键判断抽成可测试函数，同时保留 Rust 端可见性守卫。

## 验收标准

1. 工作区历史改动已按主题提交，不再以一个超大提交混合全部模块。
2. `npm audit --omit=dev` 无高危生产依赖告警。
3. 本地和 CI 使用同名依赖审计脚本。
4. `MusicWindow.vue` 行数减少，拆出的模块有测试且行为保持一致。
5. 宠物生命周期新增测试通过，默认主题和 `animal-island` 均纳入检查。
6. `npm run check:ci`、`git diff --check` 和隐私扫描通过。
7. 未提交或提交内容不包含本机配置、密钥、凭据、音乐路径、播放 URL 或用户导入资源。

## 实施结果

- [x] 历史工作区已按发布工程、后端安全、桌宠交互和音乐沉浸体验形成独立中文提交。
- [x] `postcss` 与 `nanoid` 已升级到安全修复版本，生产依赖审计为零漏洞。
- [x] 本地 `check:ci` 和 GitHub Quality 工作流统一调用 `audit:prod`。
- [x] 音乐库、队列和自定义歌单规范化已拆到 `src/utils/musicLibraryModel.ts`，并有独立单元测试。
- [x] 宠物窗口已覆盖默认主题和 `animal-island` 主题的事件注册、卸载清理、快捷键注销和气泡关闭测试；Rust 端补充隐藏宠物禁止显示气泡的策略测试。
