# 未完成功能评估与后续实施计划

本文档用于评估当前未完成功能的优先级，并规划后续开发顺序。本文档只记录通用功能计划，不记录用户本机路径、AI API Key、Base URL、音乐文件、导入素材、平台凭据、Codex 会话内容、运行历史或其他隐私数据。

## 评估原则

1. 先做能支撑多个功能的底层能力，再做单点体验增强。
2. 优先保证现有已完成能力稳定，不把新功能建立在未验证状态上。
3. 涉及前端界面的新增窗口、弹窗、按钮、输入框、列表、空状态和错误提示，必须同时检查默认主题和 `animal-island` 主题。
4. 音乐、宠物素材、Codex 状态和用户配置都只作为本机运行时数据处理，不写入源码、示例文档或仓库。
5. 大功能分阶段交付，每一阶段都应能独立构建、验证和回退。

## 推荐总路线

1. 已完成：收口当前工作区状态、构建基线和文档索引。
2. 下一步：实现 `hatch-pet` 到 PetDrawer 的本机离线转换器。
3. 同步推进：Codex 状态聚合真实环境回归和工程维护优化。
4. 然后：基于宠物状态模型接入音乐播放动画联动。
5. 再逐步做音乐体验深化、在线平台兜底、歌单管理和可选沉浸视觉增强。
6. 最后穿插处理图标提取、宠物气泡、翻译可选能力和跨平台细节。

## 阶段 1：AI 宠物素材离线转换器 MVP

目标：打通“外部生成素材 -> 转换格式 -> 导入 PetDrawer”的稳定流程，不先做应用内生成 UI。

交付内容：

- 输入为 `hatch-pet` 运行目录、Codex pet atlas、动作行素材目录或生成结果目录。
- 支持把 `idle`、`running-left`、`running-right`、`waving`、`jumping`、`failed`、`waiting`、`running`、`review` 映射为 PetDrawer 动画状态。
- 输出 PetDrawer 可导入的动画文件和 `pet.json`。
- 输出文件不覆盖同名文件，必要时自动追加后缀。
- 缺少可选状态时在摘要中说明并回退，不让导入流程失败。
- 使用临时测试素材验证转换器，不把用户参考图、生成素材或本机路径写入仓库。

验收标准：

- 至少能生成一个包含 `idle` 的可导入宠物包。
- 多状态包能在 PetDrawer 中预览并播放。
- 失败信息可理解，不暴露完整本机路径、密钥或 token。
- 默认主题和 `animal-island` 主题下导入 UI 正常。

## 阶段 2：Codex 多任务状态聚合回归

当前状态：代码级大部分完成。

目标：让宠物可靠表达 Codex 的运行、等待、完成和失败状态，同时保持低打扰。

交付内容：

- 在 `proxy`、`managed`、`sessionLog` 三种模式下回归任务事件链路。
- 验证运行时任务表、聚合摘要、脱敏最近任务列表、未读计数和确认入口。
- 验证等待、失败、完成、运行、检查等状态优先级。
- 评估低频重复提醒、声音提醒和聚合展示细节。

验收标准：

- 多个 Codex 任务同时存在时，状态不会被最后一个普通事件错误覆盖。
- 等待用户处理和失败状态优先展示。
- 完成状态不会打断仍在运行的其他任务。
- 默认主题和 `animal-island` 主题下气泡、角标、任务摘要可读。

## 阶段 3：工程维护优化

目标：降低后续功能迭代的维护成本，避免超大单文件继续堆叠。

交付内容：

- 拆分 `MusicWindow.vue` 中的在线平台、沉浸模式、迷你播放器、本地库和设置逻辑。
- 拆分 `kugou_music.rs`、`ai_chat.rs`、`DrawerWindow.vue` 等高复杂度文件。
- 复查注册命令，清理确认无前端、托盘、窗口或兼容需求的接口。
- 继续优化构建分包和懒加载边界。
- 增加或整理常用检查脚本。

验收标准：

- 单次拆分不改变用户可见行为。
- `npm run build`、严格未使用检查和 `cargo check` 通过。
- 默认主题和 `animal-island` 主题不受拆分影响。
- 隐私关键词扫描无真实密钥或用户数据。

## 阶段 4：音乐播放状态和宠物动画联动

目标：把已完成的音乐播放器能力转化为桌宠可感知的陪伴反馈。

交付内容：

- 建立音乐播放事件到宠物动画状态的映射。
- 播放中、暂停、切歌、收藏、睡眠音乐、专注音乐等动作有最小动画反馈。
- 先使用现有宠物状态回退规则，不要求每个宠物包都有专用音乐动画。
- 增加用户说“这首不错”时的本地偏好反馈逻辑：询问是否收藏或提高本地推荐权重。
- AI 推荐只使用标签、收藏、最近播放、播放次数等安全摘要，不上传歌曲路径或音频内容。
- 设置项提供是否启用音乐动画联动、是否允许 AI 主动推荐、是否允许 AI 自动播放等开关。

验收标准：

- 音乐播放、暂停、切歌、收藏能触发对应宠物反馈。
- 关闭音乐联动后，音乐指令只按普通聊天或播放器操作处理。
- 默认主题和 `animal-island` 主题下新增设置和状态提示正常。
- 不写入歌曲真实路径、存储目录、播放列表或本地资源到源码和文档示例。

## 阶段 5：音乐体验和在线平台深化

目标：在基础联动稳定后，再补完整音乐体验。

建议顺序：

1. 完整歌单管理：歌单封面、批量维护、排序体验和空状态。
2. 完整标签系统：标签分组管理、批量打标签、标签权重和推荐解释。
3. 封面和歌词：仅本机读取 metadata 或本机文件，不接入音频指纹识别或外部上传服务。
4. 情绪陪伴模式：基于聊天内容、时间段和本地标签推荐音乐。
5. 专注和睡眠模式：定时、音量渐变、降低宠物动作频率、减少打扰。
6. 网易云和酷狗播放兜底、失败诊断和歌单管理增强。
7. 可选沉浸视觉增强，例如 Butterchurn 或原生长音频解码回退。

验收标准：

- 每个子功能都有明确开关和退出路径。
- 不上传原始音频、音频指纹、歌曲路径或识别服务密钥。
- 本机数据迁移和兼容策略清晰。

## 阶段 6：低风险打磨项

目标：穿插处理不阻塞主线但能改善体验的小项。

抽屉图标提取：

- 增加图标提取失败时的分级建议。
- 支持多尺寸图标手动选择。
- 非 Windows 平台提供替代方案或明确降级提示。

宠物气泡：

- 增加更多气泡类型。
- 支持用户手动位置偏好。
- 优化多显示器、缩放比例和屏幕边缘场景。

翻译：

- 历史记录、专用翻译 API、PDF/OCR 等能力需另起需求文档。
- 新增任何历史或外部 API 时，必须重新确认隐私和密钥保存边界。

验收标准：

- 不改变已有主流程。
- 不记录用户本机软件路径、文件路径、音乐路径、翻译原文、Codex 内容或平台凭据。
- 两套主题下样式可读、无重叠、无溢出。

## 每阶段通用检查清单

1. 开发前确认是否需要新增或更新需求计划文档。
2. 修改代码前读取 `docs/RELEASE_PRIVACY_CHECKLIST.md`。
3. 涉及前端时同时检查默认主题和 `animal-island` 主题。
4. 涉及用户数据时确认只写入本机运行时存储。
5. 构建或类型检查通过后再更新完成记录。
6. 提交前检查 `git status --short`、`.gitignore` 和疑似密钥关键词扫描结果。
7. 不主动提交、推送或发布 Release，除非用户明确要求。
