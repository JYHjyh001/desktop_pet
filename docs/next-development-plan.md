# 未完成功能评估与后续实施计划

本文档用于评估当前未完成功能的优先级，并规划后续开发顺序。本文档只记录通用功能计划，不记录用户本机路径、AI API Key、Base URL、音乐文件、导入素材、Codex 会话内容、运行历史或其他隐私数据。

## 评估原则

1. 先做能支撑多个功能的底层能力，再做单点体验增强。
2. 优先保证现有已完成能力稳定，不把新功能建立在未验证状态上。
3. 涉及前端界面的新增窗口、弹窗、按钮、输入框、列表、空状态和错误提示，必须同时检查默认主题和 `animal-island` 主题。
4. 音乐、宠物素材、Codex 状态和用户配置都只作为本机运行时数据处理，不写入源码、示例文档或仓库。
5. 大功能分阶段交付，每一阶段都应能独立构建、验证和回退。

## 推荐总路线

后续不建议直接从“应用内 AI 生成宠物”或“第三方音乐平台接入”开始。这两类功能对隐私、外部依赖、失败处理和 UI 复杂度要求高，容易拉长周期。

推荐先走这条主线：

1. 已完成：收口当前工作区状态和构建基线。
2. 已完成：扩展宠物动画状态模型，保持旧宠物包兼容。
3. 下一步：实现 `hatch-pet` 到 PetDrawer 的本机转换器。
4. 已有代码级实现，待真实环境回归：基于多状态宠物接入 Codex 运行状态聚合。
5. 基于同一套状态模型接入音乐播放动画联动。
6. 再逐步做音乐推荐、专注/睡眠模式、歌词封面和第三方音乐入口。
7. 最后穿插处理图标提取和宠物气泡的可选增强。

## 阶段 0：当前状态收口

当前状态：已完成。已检查工作区变更范围、隐私检查规则和构建基线；`npm run build` 与后端检查在本轮对照前已通过。

目标：在继续开发前确认现有修改不会影响后续判断。

交付内容：

- 检查 `git status --short`，确认当前已修改文件范围。
- 读取 `.gitignore` 和 `docs/RELEASE_PRIVACY_CHECKLIST.md`，确认本机配置、密钥、打包缓存和用户数据不会进入提交范围。
- 执行一次前端构建或类型检查，记录当前基线是否通过。
- 如当前工作区已有未完成改动，先不重构 unrelated 文件，后续只在明确功能范围内修改。

验收标准：

- 当前工作区状态可解释。
- 隐私检查没有发现真实密钥、本机配置或用户数据进入仓库。
- 后续每个阶段都能基于明确基线继续。

## 阶段 1：宠物多状态模型和导入兼容

当前状态：已完成。类型、默认素材 manifest、导入/更新结构、编辑预览 UI、运行时播放和旧宠物包回退规则均已支持新增状态。

目标：先让 PetDrawer 能保存、导入、预览和播放更多宠物状态，为 AI 宠物素材、Codex 状态和音乐联动打基础。

交付内容：

- 保留旧状态：`idle`、`hover`、`click`、`dragging`。
- 新增可选状态：`waiting`、`running`、`review`、`failed`、`waving`、`jumping`、`draggingLeft`、`draggingRight`。
- 旧宠物包缺少新状态时按规则回退到 `dragging` 或 `idle`，不破坏现有宠物。
- 拖动宠物时根据横向移动方向选择 `draggingLeft` 或 `draggingRight`。
- 导入、编辑、预览 UI 支持新增状态，并避免小窗口下文字溢出。
- 默认主题和 `animal-island` 主题都补齐新增状态标签、按钮、空状态和错误提示样式。

验收标准：

- 旧版 4 状态宠物包仍能正常使用。
- 新宠物包可以保存和读取新增状态。
- 拖动方向动画切换正常，没有动画状态抖动。
- `npm run build` 通过。

## 阶段 2：AI 宠物素材离线转换器 MVP

目标：先打通“外部生成素材 -> 转换格式 -> 导入 PetDrawer”的稳定流程，不先做应用内生成 UI。

交付内容：

- 新增本机转换流程，输入为 `hatch-pet` 运行目录或动作行素材目录。
- 支持把 `idle`、`running-left`、`running-right`、`waving`、`jumping`、`failed`、`waiting`、`running`、`review` 映射为 PetDrawer 动画状态。
- 输出 PetDrawer 可导入的动画文件和 `pet.json`。
- 输出文件不覆盖同名文件，必要时自动追加后缀。
- 缺少可选状态时在摘要中说明并回退，不让导入流程失败。
- 使用临时测试素材验证转换器，不把用户参考图、生成素材或本机路径写入仓库。

验收标准：

- 至少能生成一个包含 `idle` 的可导入宠物包。
- 多状态包能在 PetDrawer 中预览并播放。
- 失败信息可理解，不暴露完整本机路径、密钥或 token。
- 默认主题和 `animal-island` 主题下导入 UI 正常。

## 阶段 3：Codex 多任务状态聚合

当前状态：代码级大部分完成。已具备运行时任务表、聚合摘要、脱敏最近任务列表、未读计数、确认入口和两套主题样式；仍需要在真实 `proxy`、`managed`、`sessionLog` 环境下回归验证，并继续评估低频重复提醒等可选增强。

目标：让宠物能可靠表达 Codex 的运行、等待、完成和失败状态，同时保持低打扰。

交付内容：

- 后端维护运行时任务表，只保存脱敏任务标识、状态、更新时间和短文案。
- 聚合优先级按 `waiting`、`failed`、`completed`、`running/review`、`connected`、`disconnected` 处理。
- 宠物动画接入 `waiting`、`running`、`review`、`failed`、`jumping`、`waving` 等状态。
- 完成后保留轻量完成数量角标或状态提示，用户悬浮或点击后确认。
- 设置区域显示脱敏的最近任务摘要，不展示 prompt、assistant 正文、终端输出、项目路径或日志路径。
- `proxy`、`managed`、`sessionLog` 模式继续遵守本机处理和脱敏要求。

验收标准：

- 多个 Codex 任务同时存在时，状态不会被最后一个普通事件错误覆盖。
- 等待用户处理和失败状态优先展示。
- 完成状态不会打断仍在运行的其他任务。
- 默认主题和 `animal-island` 主题下气泡、角标、任务摘要可读。
- `npm run build` 和后端检查通过。

## 阶段 4：音乐播放状态和宠物动画联动

目标：把已完成的音乐播放器能力转化为桌宠可感知的陪伴反馈。

交付内容：

- 建立音乐播放事件到宠物动画状态的映射。
- 播放中、暂停、切歌、收藏、睡眠音乐、专注音乐等动作有最小动画反馈。
- 先使用现有宠物状态回退规则，不要求每个宠物包都有专用音乐动画。
- 增加用户说“这首不错”时的本地偏好反馈逻辑：询问是否收藏或提高本地推荐权重。
- AI 推荐只使用标签、收藏、最近播放、播放次数等安全摘要，不上传歌曲路径或音频内容。
- 设置项提供是否启用音乐动画联动、是否允许 AI 主动推荐、是否允许 AI 自动播放等开关。

验收标准：

- 音乐播放、暂停、切歌、收藏能触发对应宠物反馈。
- 关闭音乐联动后，音乐指令只按普通聊天或播放器操作处理。
- 默认主题和 `animal-island` 主题下新增设置和状态提示正常。
- 不写入歌曲真实路径、存储目录、播放列表或本地资源到源码和文档示例。

## 阶段 5：音乐体验深化

目标：在基础联动稳定后，再补完整音乐体验。

建议顺序：

1. 完整歌单管理：歌单封面、批量维护、排序体验和空状态。
2. 完整标签系统：标签分组管理、批量打标签、标签权重和推荐解释。
3. 封面和歌词：仅本机读取 metadata 或本机文件，不接入音频指纹识别或外部上传服务。
4. 情绪陪伴模式：基于聊天内容、时间段和本地标签推荐音乐。
5. 专注和睡眠模式：定时、音量渐变、降低宠物动作频率、减少打扰。
6. 起床、跳舞和剧情音乐模式：在基础模式稳定后作为增强体验。
7. 第三方音乐平台：优先做跳转或控制本机客户端，再考虑官方 API。

验收标准：

- 每个子功能都有明确开关和退出路径。
- 不上传原始音频、音频指纹、歌曲路径或识别服务密钥。
- 本机数据迁移和兼容策略清晰。

## 阶段 6：低风险打磨项

目标：穿插处理不阻塞主线但能改善体验的小项。

抽屉图标提取：

- 增加图标提取失败时的分级建议。
- 支持多尺寸图标手动选择。
- 非 Windows 平台提供替代方案或明确降级提示。

宠物气泡：

- 增加更多气泡类型。
- 支持用户手动位置偏好。
- 优化多显示器、缩放比例和屏幕边缘场景。

验收标准：

- 不改变已有主流程。
- 不记录用户本机软件路径、文件路径或 Codex 内容。
- 两套主题下样式可读、无重叠、无溢出。

## 不建议立即启动的事项

- 应用内 AI 宠物生成入口：需要先有稳定转换器和导入体验。
- 第三方音乐软件深度控制：涉及外部应用差异、登录、版权和隐私边界，应该后置。
- 非 Windows 图标自动提取：当前项目主要运行规则围绕 Windows 桌宠，跨平台收益低于宠物状态和音乐联动。
- 复杂重复提醒和声音提醒：容易打扰用户，应等 Codex 聚合状态稳定后再评估。

## 每阶段通用检查清单

1. 开发前确认是否需要新增或更新需求计划文档。
2. 修改代码前读取 `docs/RELEASE_PRIVACY_CHECKLIST.md`。
3. 涉及前端时同时检查默认主题和 `animal-island` 主题。
4. 涉及用户数据时确认只写入本机运行时存储。
5. 构建或类型检查通过后再更新完成记录。
6. 提交前检查 `git status --short`、`.gitignore` 和疑似密钥关键词扫描结果。
7. 不主动提交、推送或发布 Release，除非用户明确要求。
