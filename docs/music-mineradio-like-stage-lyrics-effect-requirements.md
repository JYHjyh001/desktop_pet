# Mineradio 风格舞台歌词效果需求计划

本文档记录沉浸音乐舞台歌词效果增强方案。本功能只调整前端视觉呈现和运行态音乐响应，不保存用户歌曲路径、播放 URL、歌词文本、平台 Cookie、token、音频数据或本机运行历史。

## 背景

当前沉浸模式已经具备星河漫游、地面 DJ、歌词舞台、逐句/逐字进度、歌词参数调节和音乐包络响应。用户希望舞台歌词效果进一步接近 Mineradio 的歌词舞台观感：歌词像真实舞台中的发光文字平面，与粒子、镜头、节奏和地面投影更紧密地融合。

Mineradio 仓库采用 GPL-3.0，并声明名称、界面视觉设计与原创视觉表达归作者所有。本项目只参考公开 README 与本地临时阅读得到的高层视觉原则，自研实现，不复制第三方代码、资源、命名素材或原始视觉表达。

## 目标

1. 让当前歌词具备更明确的舞台平面感：文字前景、可读描边、柔光核心、空气光带、地面投影和反射层次要更清楚。
2. 歌词换句必须保持和音频时间轴即时同步：当前句直接替换，不增加入场/退场动画、强制重建或延迟切换层。
3. 音乐响应从单纯抖动改成分层响应：低频推动轻微前移和抬升，中高频推动空气光和微粒，歌词行进度推动高亮扫过。
4. 地面 DJ 预设下歌词应更像悬在柱阵中心上方，反光投影更稳定；星河漫游下歌词应更像漂浮在星云前方。
5. 默认主题与 `animal-island` 主题都要保持歌词可读，状态标签、空歌词、错误提示和只看舞台模式不能遮挡主视觉。

## 非目标

1. 不把歌词改成 WebGL 贴图实现，避免大幅重写现有 DOM 歌词同步、可读性和逐字进度逻辑。
2. 不复制 Mineradio 的 Three.js 文字平面、shader、纹理生成、资源或参数表。
3. 不新增歌词文本、歌曲路径、播放链接、平台凭据或音频数据的持久化字段。
4. 不改网易云、酷狗、本地歌曲的播放链路和歌词读取链路。
5. 不新增外部识别、音频指纹、上传音频或联网歌词识别服务。

## 实现步骤

1. 阅读 `docs/RELEASE_PRIVACY_CHECKLIST.md`，确认本次改动不触碰用户隐私数据。
2. 阅读 Mineradio 的 README、LICENSE 和歌词舞台相关代码片段，只提炼视觉原则。
3. 在 `src/windows/MusicWindow.vue` 中扩展歌词运行态 CSS 变量：区分日光溢光、焦点强度、反射强度和舞台跟随量。
4. 在 `src/styles.css` 中增强歌词舞台结构：增加文字形态外羽化、聚焦光带、地面椭圆投影、当前句反射和预设差异；当前句切换不做入场/退场动画，歌词层不再绘制背景光点。
5. 检查默认主题与 `animal-island` 主题，补齐必要的主题覆盖样式。
6. 运行前端构建和隐私关键词检查。
7. 功能完成后记录到 `docs/completed-features.md`。

## 验收标准

- [x] 当前歌词有更强的发光文字平面感，进度高亮、文字描边和外部羽化同时存在。
- [x] 换句时当前句即时替换，不通过 Transition、强制 key 重建或入退场动画制造延迟。
- [x] 星河漫游与地面 DJ 下歌词位置、投影和光晕有差异，不像同一套样式简单换色。
- [x] 降低动态时禁用明显漂移，只保留静态层次；星河光点由 WebGL 舞台负责，不在歌词背景重复绘制。
- [x] 默认主题和 `animal-island` 主题下歌词、状态标签、空状态和错误提示可读。
- [x] 不新增用户歌词文本、歌曲路径、播放 URL、Cookie、token、音频数据或本机运行历史持久化。
