# 沉浸歌词与在线播放稳定性优化需求计划

本文档记录沉浸模式歌词布局、连续在线播放稳定性和沉浸播放列表窗口的本次优化计划。该功能只调整运行态播放器体验，不把用户歌曲路径、播放 URL、Cookie、token、歌单内容或本机资源写入源码、示例文档或仓库。

## 背景

- 沉浸模式当前歌词区使用固定主歌词高度，长歌词换行超过三行时可能和上一句、下一句重合。
- 在线歌曲连续播放后，部分场景会出现整首歌曲反复缓冲、播放几秒又进入缓冲的问题。
- 沉浸模式左侧播放列表当前只取列表前若干首，不便于在长歌单里查看当前歌曲附近的上下文。

## 目标

- 歌词区域根据当前歌词和上下句的预估行数自动调整高度、间距和主歌词字号，避免三行以上歌词与上下句重叠。
- 在线歌曲发生连续 `waiting` / `stalled` 时，恢复逻辑只作用于当前歌曲和当前播放请求，切歌后旧计时器不影响新歌。
- 沉浸模式左侧播放列表围绕当前播放歌曲展示上下最多 50 首，并保留当前歌曲高亮。
- 默认主题和 `animal-island` 主题下沉浸歌词、播放列表、空状态和错误提示都保持可读且不重叠。

## 设计方案

### 歌词布局

- 为沉浸歌词层增加运行态布局变量，根据歌词文字长度估算当前句和上下句行数。
- 当前歌词允许最多四行展示，行数增加时降低主歌词字号，并增加主歌词容器高度和上下间距。
- 上一句和下一句允许最多两行展示，避免长翻译或长歌词被强制压成一行后信息缺失。
- 当歌词为空、错误或间奏时沿用低打扰状态，但仍使用相同高度规则避免布局跳动。

### 播放稳定性

- 在线播放进入新歌曲、暂停、切歌、自然恢复时重置卡顿恢复状态，防止旧恢复计时器继续刷新新歌曲链路。
- 对连续缓冲做节流：只有在播放进度没有自然前进、媒体 `readyState` 仍不足时才刷新播放链路。
- 刷新链路后重新加载当前运行态播放 URL，并在当前位置继续播放；失败时给出可理解错误，不隐藏会员、版权、地区或网络限制。

### 沉浸播放列表窗口

- 本地、网易云、酷狗三类沉浸列表都以当前播放上下文为主。
- 当前歌曲在列表中时，展示当前歌曲前最多 50 首和后最多 50 首；列表不足时展示已有范围。
- 当当前歌曲不在可用上下文中时，退回当前来源的前 101 首，避免空列表。
- 列表标题补充“当前附近”语义，让用户知道这不是完整歌单。

## 验收标准

- 长歌词换行到三行或四行时，不与上一句、下一句发生重叠。
- 连续切歌后不会由上一首的缓冲恢复计时器刷新当前新歌。
- 在线歌曲轻微缓冲时优先等待自然恢复，长时间无数据时才刷新临时播放链路。
- 沉浸模式左侧列表能围绕当前歌曲显示上下最多 50 首，当前歌曲保持高亮。
- 默认主题和 `animal-island` 主题下界面文字、按钮、列表和错误提示可读。
- `npm run build` 通过。
- 隐私检查通过，不提交本机配置、密钥、用户路径、播放 URL 或打包产物。

## 2026-07-13 主歌词加载时机修复

### 问题

- 沉浸内容准备原本统一延迟 1.4 秒执行；切歌或播放状态变化会取消该定时任务，导致主歌词未读取，重新进入沉浸模式后才重新触发。

### 完成方案

- [x] 进入沉浸模式时立即读取当前歌曲歌词，不再等待可视化内容准备定时器。
- [x] 沉浸模式内当前歌曲变化时，重置旧歌词后立即读取新歌曲歌词。
- [x] 节奏图分析继续延迟执行，避免切歌初期与音频播放争用资源。
- [x] 保留延迟歌词调用作为幂等兜底；歌词已处于读取中或已就绪时不会重复请求。
- [x] 默认主题和 `animal-island` 主题均覆盖“进入沉浸模式后从我的歌单切歌”的回归测试。
- [x] 测试只使用通用虚拟歌曲路径和歌词，不包含用户本机歌曲、路径、账号或平台凭据。

## 2026-07-13 在线歌词超时与重复请求修复

### 问题

- 在线歌词沿用本机歌词的 15 秒前端超时，但酷狗歌词需要顺序完成候选搜索和歌词下载，两段后端请求的总耗时可能超过 15 秒。
- 在沉浸模式播放网易云或酷狗歌曲时，主歌词 composable 与普通平台歌词面板会同时请求同一首歌词，造成重复网络请求和完成顺序竞态。

### 完成方案

- [x] 本机歌词继续使用 15 秒超时，网易云和酷狗在线歌词单独使用 45 秒超时，覆盖后端已有的网络超时边界。
- [x] 沉浸模式只由主歌词链路请求歌词；普通音乐窗口仍保留平台歌词面板的自动读取能力。
- [x] 在线歌词超过原 15 秒阈值后保持加载状态，响应返回后直接显示，不需要退出并重新进入沉浸模式。
- [x] 增加慢速在线歌词测试，模拟超过 15 秒后返回并验证最终进入就绪状态。

## 2026-07-13 WebGL 当前主歌词消失修复

### 问题

- WebGL 当前句会随逐字进度高频重绘，但旧实现每次重绘都重新写入 Canvas 的宽高；即使尺寸没有变化，也会清空并重新分配 Canvas 位图，WebView2 的 CanvasTexture 连续上传期间可能短暂或持续得到空纹理。上一句和下一句只在换行时重绘，因此会出现“两侧句子正常、中间主句消失”的特征。
- 切歌、歌词加载和播放状态会在很短时间内连续变化，换行位移动画可能只渲染起始帧便被渲染循环切换中断；当前句因此停在下一句位置，中央保持空白。退出沉浸模式会重建 WebGL 歌词状态，所以重新进入后暂时恢复。
- 已同步复查歌词状态、空行过滤、纹理透明度和地面 DJ 深度关系：当前句状态包含有效文本；歌词材质关闭深度测试且处于透明渲染阶段，地形不是本次中间句消失的原因。

### 完成方案

- [x] Canvas 位图尺寸只在真实变化时调整；逐字进度重绘不再反复重置宽高和纹理存储。
- [x] 移除依赖后续渲染帧完成的三行位移补间；当前句始终直接落在中央，上下句直接落在各自目标位置。
- [x] 增加 Canvas 位图尺寸稳定性测试，覆盖连续同尺寸重绘和单维度变化。
- [x] 默认主题和 `animal-island` 主题继续共用同一套 WebGL 歌词修复，不增加主题专属分支。

## 2026-07-13 歌词与 WebGL 纹理生命周期解耦

### 最终定位

- 连续截图证明上一句和下一句已经随新歌曲更新，歌词请求、解析和当前时间窗口不是阻塞点。
- 当前句单独消失且退出重进后恢复，说明故障集中在当前句 CanvasTexture 的运行时纹理状态；仅调整超时、重复请求、Canvas 尺寸或补间条件无法保证 WebView2/GPU 组合下稳定恢复。

### 完成方案

- [x] WebGL 继续负责星河、频谱、地形和音乐能量视觉，不关闭沉浸舞台。
- [x] 三行歌词改由现有 DOM 歌词层唯一渲染；歌词响应式状态变化后直接更新文本，不再依赖 CanvasTexture 上传。
- [x] 保留逐句进度、长歌词布局、空态、错误态和间奏状态。
- [x] 默认主题与 `animal-island` 继续使用各自现有 DOM 歌词样式。
- [x] 音乐窗口测试改为直接断言沉浸 DOM 当前句，覆盖切歌后无需退出重进的行为。
