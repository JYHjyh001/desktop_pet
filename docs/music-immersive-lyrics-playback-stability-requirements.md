# 沉浸歌词与在线播放稳定性优化需求计划

本文档记录沉浸模式歌词布局、连续在线播放稳定性和沉浸播放列表窗口的本次优化计划。该功能只调整运行态播放器体验，不把用户歌曲路径、播放 URL、Cookie、token、歌单内容或本机资源写入源码、示例文档或仓库。

## 背景

- 沉浸模式当前歌词区使用固定主歌词高度，长歌词换行超过三行时可能和上一句、下一句重合。
- 在线歌曲连续播放后，部分场景会出现整首歌曲反复缓冲、播放几秒又进入缓冲的问题。
- 沉浸模式左侧播放列表当前只取列表前若干首，不便于在长歌单里查看当前歌曲附近的上下文。

## 目标

- 歌词区域根据当前歌词和上下句的预估行数自动调整高度、间距和主歌词字号，避免三行以上歌词与上下句重叠。
- 在线歌曲发生连续 `waiting` / `stalled` 时，恢复逻辑只作用于当前歌曲和当前播放请求，切歌后旧计时器不影响新歌。
- 沉浸模式左侧播放列表围绕当前播放歌曲展示上下最多 50 首，并保留当前歌曲高亮。
- 默认主题和 `animal-island` 主题下沉浸歌词、播放列表、空状态和错误提示都保持可读且不重叠。

## 设计方案

### 歌词布局

- 为沉浸歌词层增加运行态布局变量，根据歌词文字长度估算当前句和上下句行数。
- 当前歌词允许最多四行展示，行数增加时降低主歌词字号，并增加主歌词容器高度和上下间距。
- 上一句和下一句允许最多两行展示，避免长翻译或长歌词被强制压成一行后信息缺失。
- 当歌词为空、错误或间奏时沿用低打扰状态，但仍使用相同高度规则避免布局跳动。

### 播放稳定性

- 在线播放进入新歌曲、暂停、切歌、自然恢复时重置卡顿恢复状态，防止旧恢复计时器继续刷新新歌曲链路。
- 对连续缓冲做节流：只有在播放进度没有自然前进、媒体 `readyState` 仍不足时才刷新播放链路。
- 刷新链路后重新加载当前运行态播放 URL，并在当前位置继续播放；失败时给出可理解错误，不隐藏会员、版权、地区或网络限制。

### 沉浸播放列表窗口

- 本地、网易云、酷狗三类沉浸列表都以当前播放上下文为主。
- 当前歌曲在列表中时，展示当前歌曲前最多 50 首和后最多 50 首；列表不足时展示已有范围。
- 当当前歌曲不在可用上下文中时，退回当前来源的前 101 首，避免空列表。
- 列表标题补充“当前附近”语义，让用户知道这不是完整歌单。

## 验收标准

- 长歌词换行到三行或四行时，不与上一句、下一句发生重叠。
- 连续切歌后不会由上一首的缓冲恢复计时器刷新当前新歌。
- 在线歌曲轻微缓冲时优先等待自然恢复，长时间无数据时才刷新临时播放链路。
- 沉浸模式左侧列表能围绕当前歌曲显示上下最多 50 首，当前歌曲保持高亮。
- 默认主题和 `animal-island` 主题下界面文字、按钮、列表和错误提示可读。
- `npm run build` 通过。
- 隐私检查通过，不提交本机配置、密钥、用户路径、播放 URL 或打包产物。
