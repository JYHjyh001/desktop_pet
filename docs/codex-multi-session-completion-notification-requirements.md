# Codex 多会话状态聚合与完成提醒需求计划

## 背景

当前 Codex 状态提醒已经能监听单个全局状态，并在宠物窗口显示气泡。但当用户同时使用 Codex 处理多个对话或多个项目时，现有状态会被后到事件覆盖，用户无法区分是一个任务、多个任务、哪个任务需要处理，完成提示也可能因为气泡自动消失而被错过。

本计划用于优化 Codex 状态提醒的聚合逻辑和完成提醒表现。所有 Codex 数据仍只在本机运行时处理，不展示、不保存 Codex 对话正文、终端输出、工具输出、本机项目路径或用户隐私数据。

## 目标

1. 支持同时聚合多个 Codex 线程或会话日志的状态。
2. 宠物气泡显示聚合后的关键状态，而不是只显示最后一个事件。
3. 完成、失败、等待用户处理这三类状态必须比普通运行状态更明显。
4. 工作完成后即使气泡消失，也要保留一个可见的未读完成提示，直到用户确认或自然过期。
5. 设置页 Codex 区域显示最近任务状态摘要，方便用户回看。
6. 默认主题和 `animal-island` 主题都要有对应样式。

## 非目标

1. 不读取或展示 Codex prompt、assistant 正文、工具输出或终端输出。
2. 不展示真实项目路径、工作目录、日志文件路径或本机绝对路径。
3. 不把 Codex 会话详情持久化到源码、文档示例或仓库。
4. 不替代 Codex 客户端的任务管理，只提供桌宠侧提醒和摘要。
5. 不默认播放声音，避免打扰；声音提醒可以作为后续可选设置。

## 状态模型

### 任务标识

后端维护运行时任务表，任务键只用于本机内存聚合：

- `proxy` 和 `managed` 模式优先使用 `threadId`，缺失时使用 `turnId`。
- `sessionLog` 模式使用现有脱敏会话显示标识，不使用日志文件真实路径。
- 任务表只保留有限数量的最近任务，例如 20 条。

### 单任务状态

每个任务记录以下脱敏字段：

- `id`：脱敏任务标识。
- `mode`：`proxy`、`managed` 或 `sessionLog`。
- `state`：`running`、`review`、`waiting`、`completed`、`failed`、`connected`。
- `lastEvent`：事件类型。
- `updatedAt`：更新时间。
- `unread`：完成、失败、等待处理是否仍未确认。
- `message`：脱敏状态短文案，例如“Codex 工作完成”。

### 聚合状态优先级

宠物气泡和设置页顶部使用聚合状态，按以下优先级选择主状态：

1. `waiting`：需要用户处理审批或输入，最高优先级。
2. `failed`：任务失败或中断。
3. `completed`：存在未读完成提醒。
4. `running` 或 `review`：仍有任务运行。
5. `connected`：已连接但当前空闲。
6. `disconnected`：未监听。

### 聚合文案

气泡不显示真实线程 ID 或路径，只显示数量和状态：

- 1 个任务运行：`Codex 正在工作`
- 多个任务运行：`Codex：2 个任务进行中`
- 有等待处理：`Codex：1 个任务需要处理`
- 有失败：`Codex：1 个任务失败`
- 有未读完成：`Codex：2 个任务已完成`
- 多状态混合：优先显示更需要关注的状态，例如等待处理优先于完成。

## 完成提醒方案

### 第一层：明显气泡

任务完成时显示更明显的完成气泡：

- 气泡显示时间从当前短时展示调整为更长时间，例如 12 秒。
- 完成气泡使用 `completed` 状态专属样式。
- 多任务完成时显示数量，例如 `Codex：2 个任务已完成`。
- 气泡最多两行，避免遮挡宠物主体。

### 第二层：宠物动作

任务完成时宠物执行更明显的动作序列：

1. 先播放 `jumping` 动画。
2. 如果有 `waving` 动画，随后短暂播放 `waving`。
3. 若当前仍有其他任务运行，完成动作结束后回到 `running` 或 `review`，而不是直接回到 `idle`。

### 第三层：未读完成徽标

气泡消失后，如果用户还没有确认完成提醒，宠物窗口保留一个小徽标：

- 徽标显示在宠物附近，不遮挡主体。
- 默认主题显示为绿色完成圆点或小标签。
- `animal-island` 主题显示为暖色纸片徽标。
- 徽标文本示例：
  - `完成`
  - `完成 2`
  - `失败 1`
  - `待处理 1`

### 第四层：轻微重复提醒

如果用户长时间没有确认，允许低频重复提醒：

- 完成提醒：每 30 秒轻微闪烁一次，最多 3 次。
- 等待处理：每 20 秒重复显示气泡，直到状态解除或用户确认。
- 失败提醒：不高频重复，保留徽标并在设置页可见。

### 确认方式

用户可通过以下动作确认提醒：

- 点击宠物气泡。
- 点击宠物完成徽标。
- 打开设置页的 Codex 区域。
- 点击设置页里的“清除已读提醒”。

确认后：

- 完成和失败的 `unread` 变为 `false`。
- 徽标根据剩余未读任务重新计算。
- 不清除运行中的任务状态。

## 设置页优化

Codex 设置区域新增最近任务摘要：

1. 顶部仍保留当前聚合状态卡片。
2. 新增最近任务列表，最多显示 5 条。
3. 每条只展示脱敏信息：
   - 状态标签。
   - 模式。
   - 更新时间。
   - 脱敏短标识，例如“任务 1”。
4. 提供“清除已读提醒”按钮。
5. 不显示项目路径、prompt、assistant 回复、工具输出或日志路径。

## 后端实现计划

1. 扩展 `CodexRuntime`，增加运行时任务表。
2. 扩展 `CodexStatusPayload`，保留现有字段兼容旧前端，同时新增：
   - `tasks`
   - `summary`
   - `attention`
3. 所有 `update_status` 调用在有 `thread_id` 或脱敏 `session_id` 时同步更新任务表。
4. 增加聚合函数，根据任务表计算主状态、计数和气泡文案。
5. 增加确认命令，例如 `ack_codex_notifications`，只修改运行时未读标记。
6. 对完成事件做去重，避免 `final_answer` 和 `task_complete` 重复提醒。
7. 对已完成或失败任务设置运行时过期时间，例如 30 分钟后从任务表移除。

## 前端实现计划

1. 更新 `CodexAppServerStatus` 类型，新增聚合摘要和任务列表类型。
2. 宠物窗口根据 `summary` 显示聚合气泡文案。
3. 宠物窗口增加未读提醒徽标。
4. 气泡和徽标支持点击确认。
5. 设置页 Codex 区域增加最近任务列表和清除已读入口。
6. 默认主题和 `animal-island` 主题都增加徽标、列表、空状态和错误态样式。

## 隐私要求

1. 不上传任何 Codex 状态数据到第三方服务。
2. 不保存完整 Codex 对话历史。
3. 不展示 Codex prompt、assistant 正文、工具输出、终端输出。
4. 不展示真实项目路径、工作目录、日志路径或本机绝对路径。
5. 不把任务表持久化到源码、文档示例或仓库。
6. 错误摘要继续走脱敏逻辑，避免包含敏感路径或密钥。

## 验收标准

1. 同时存在多个 Codex 任务时，气泡显示聚合数量而不是只显示最后一个普通事件。
2. 有任务等待用户处理时，聚合状态优先显示“需要处理”。
3. 有任务完成时，完成气泡显示更久，并在气泡消失后保留未读完成徽标。
4. 用户点击气泡、徽标或进入 Codex 设置区后，未读完成提示可以被确认。
5. 仍有其他任务运行时，某个任务完成不会让宠物错误回到完全空闲状态。
6. 默认主题和 `animal-island` 主题下，气泡、徽标、任务列表都清晰可见。
7. `npm run build` 和 `cargo check` 通过。
8. 敏感关键词扫描没有发现真实密钥、本机私密配置或真实项目路径。

## 建议实施阶段

### 阶段 1：运行时聚合

实现后端任务表、聚合摘要和前端聚合气泡。先不增加复杂交互，保证多任务状态准确。

### 阶段 2：完成徽标

实现未读完成徽标、确认命令和设置页清除入口。

### 阶段 3：提醒增强

增加完成动作序列、低频重复提醒和设置页最近任务列表。

### 阶段 4：体验调优

根据实际使用调整气泡时长、重复提醒间隔、任务表过期时间和主题细节。
