# 酷狗高音质播放兼容增强需求

本文档记录参考 Mineradio 的显式音质候选与实际命中档位展示方式，对当前酷狗在线播放链路进行兼容增强。本次只调整运行态播放地址获取和界面展示，不绕过会员、版权、地区、DRM、设备风控或付费限制，不保存播放 URL、Cookie、token、设备标识、歌曲路径或用户本机资源。

## 背景

- 当前酷狗链路会按音质偏好尝试多个候选，但前端只展示平台返回的格式、码率和大小。
- 酷狗会员账号在官方客户端能播放高音质时，项目可能因为接口授权、设备注册、客户端专用风控或音质不可用而回退到标准音质。
- 参考 Mineradio 的做法，应显式区分目标音质、候选顺序和实际命中档位，让用户能判断是高音质没有授权、接口没有返回，还是最终命中了标准档。

## 目标

1. 酷狗“最高可用”同时覆盖 `/v5/url` 与会员接口中的高音质候选，包括蝰蛇母带音质、蝰蛇超清音质、蝰蛇HIFI音质、蝰蛇全景声2.0、Hi-Res 音质、无损音质、高品音质和标准音质。
2. 后端播放结果返回实际命中的候选档位和标签。
3. 前端当前播放信息使用酷狗实际命中档位填充音质展示，而不是只显示格式、码率和大小。
4. 保持自动回退策略：如果高音质候选没有返回有效播放地址，继续回退到较低档位，避免可播放歌曲完全失败。
5. 用户显式选择高品、无损、Hi-Res 或蝰蛇类音质时，后端校验接口实际返回音质；如果实际返回标准音质，不把标准链接当作切换成功。
6. Hi-Res、蝰蛇类或其他高音质失败时，在错误详情中补充脱敏授权诊断字段，包括 `priv_status`、`fail_process`、`auth_through`、`tracker_through`、`trans_param`、`qualitymap` 和 `hash_offset` 摘要，帮助判断是会员包、版权、地区、风控、设备注册还是音质档位不可用。
7. 多个酷狗音源 hash、音质候选或会员接口请求体都失败时，界面只展示脱敏候选编号和关键失败摘要，避免把原始歌曲 hash 或冗长内部候选细节直接暴露给用户。
8. 会员 `/v6/priv_url` 不发送已确认不被接口接受的 `hires` quality 参数；显式选择 Hi-Res 时，播放链路只尝试登录态 `/v5/url`，如果 `/v5/url` 没有返回 Hi-Res 播放源则直接返回授权失败诊断，不继续跑会员 `/v6/priv_url` 或普通旧接口；`highest` 的会员接口候选继续尝试其他可接受的高音质档位。
9. 前端播放错误默认显示短标题、简短原因和下一步建议，完整接口诊断只放在可展开“诊断详情”中；平台歌曲行和沉浸播放列表只显示短原因，避免长诊断撑乱列表；代理读取中断类错误单独显示为“酷狗代理读取中断”，摘要解释 Range/CDN/链接续读问题，失败 Range 等细节只保留在诊断详情。
10. 播放或切换酷狗歌曲前，调用酷狗权限轻量接口预检查当前歌曲的可用音质，只返回 `available`、`unavailable` 或 `unknown` 摘要；普通设置面板和沉浸模式音质列表根据当前歌曲动态禁用已知不可用档位，Hi-Res 在不能被当前接口验证时提前标记不可用，避免继续把低音质链接当作 Hi-Res 尝试。

## 非目标

- 不读取酷狗官方客户端缓存。
- 不伪造或绕过官方客户端专用授权。
- 不把真实播放 URL、登录凭据、设备标识、本机歌曲路径、缓存路径或用户账号隐私写入源码、文档或曲库。
- 不承诺所有会员歌曲都能取得官方客户端同等高音质。
- 不在诊断详情中输出真实播放 URL、歌曲 hash、Cookie、token、设备标识或本机缓存路径。
- 不把展开的完整诊断写入本地音乐库或源码示例，只作为当前运行态界面提示。
- 不把酷狗音质可用性预检结果写入本地曲库或源码；预检缓存只保存在当前前端运行态，且不包含播放 URL。
