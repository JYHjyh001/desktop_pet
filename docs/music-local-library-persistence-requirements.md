# 本机音乐持久层和沉浸歌单改造需求计划

状态：已完成并通过前端构建、Rust 测试和完整 Tauri Release 构建验证。

## 背景

当前音乐窗口仍主要依赖前端 `localStorage` 保存歌曲列表、设置和自定义歌单。用户反馈每次打开软件都需要重新读取，说明音乐库需要迁到更稳定的本机运行时持久层。

## 隐私边界

- 音乐文件路径、歌曲存储目录、歌曲列表、队列、播放历史、收藏、分类、标签和自定义歌单都属于用户本机数据。
- 持久化文件只能保存到用户本机应用数据目录；应用数据目录可由用户在软件设置中自定义。
- 如果用户设置了歌曲文件存储目录，导入歌曲仍复制到用户选择的本机目录，并且不能覆盖同名文件。
- 不上传原始音频、音频指纹、歌曲路径、播放历史或本机目录到外部服务。
- 文档和源码示例不记录真实用户路径。

## 目标

1. 新增本机音乐库 JSON 持久层，启动时优先读取本机运行时文件。
2. 保留旧 `localStorage` 音乐数据的一次性迁移能力，避免已有列表丢失。
3. 保存歌曲列表、播放器设置、播放队列、自定义歌单和沉浸视觉设置。
4. 音乐库索引文件位置跟随应用本机数据目录，歌曲文件存储目录继续由音乐设置单独选择。
5. 沉浸模式播放列表按 Mineradio 思路拆成“当前列表”和“我的歌单”两个入口。

## 实现范围

- 后端：
  - 新增 `music-library.json` 读写能力。
  - 写入使用原子写，避免异常退出留下半截 JSON。
  - 版本和基础结构校验失败时保留原文件、生成损坏备份，并阻止前端自动写空覆盖。
  - 切换自定义基础数据目录时同步迁移音乐库和平台凭据；新旧内容冲突时保留旧文件。
  - 向聊天窗口只返回歌曲数、收藏数、最近播放数和标签的脱敏摘要。
  - 提供音乐库文件路径信息给前端展示。
- 前端：
  - 启动时读取后端音乐库状态。
  - 如果后端没有音乐库，尝试从旧 `localStorage` 迁移。
  - 修改保存逻辑为防抖写入本机 JSON。
  - 隐藏窗口、原生关闭和应用退出前 flush 待写入状态。
  - 音乐设置中展示音乐库索引位置和歌曲文件存储目录。
  - 沉浸模式左侧列表改为“当前列表 / 我的歌单”。
- 文档：
  - 更新完成/未完成记录。
  - `.gitignore` 补充音乐库本机数据文件。

## 验收

- 重启音乐窗口后，本机歌曲列表、自定义歌单、播放队列和设置不需要重新扫描即可恢复。
- 旧 `localStorage` 数据在没有新音乐库文件时可迁移到本机 JSON。
- 新导入歌曲仍遵守用户选择的歌曲文件存储目录。
- 沉浸模式可在“当前列表”和“我的歌单”之间切换。
- 默认主题和 `animal-island` 主题下，新增设置项和沉浸模式列表样式可读、无重叠。
- 音乐库损坏时不会因读取失败而自动写入空库，且可从 `.bak` 备份手动恢复。
- 宠物聊天的音乐意图上下文不包含歌名、歌手、专辑或本机路径。
